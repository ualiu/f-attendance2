# Brainstorming Frameworks

Use these frameworks to generate better ideas and evaluate them effectively.

## Idea Generation Frameworks

### SCAMPER Method
Apply each lens to the current system:

| Letter | Question | Example |
|--------|----------|---------|
| **S**ubstitute | What can be replaced? | SMS → WhatsApp, Voice, Email |
| **C**ombine | What can merge together? | Attendance + Payroll + Scheduling |
| **A**dapt | How could this fit elsewhere? | Factory → Hospital → School |
| **M**odify | What can be changed? | Real-time → Batch, Individual → Team |
| **P**ut to other uses | What else could this do? | Track inventory, equipment, vehicles |
| **E**liminate | What's not needed? | Remove points, simplify to just logging |
| **R**everse | What if we flipped it? | Employee reports → System detects automatically |

### Six Thinking Hats
Evaluate ideas from multiple perspectives:

| Hat | Focus | Questions to Ask |
|-----|-------|------------------|
| ⚪ White | Facts | What data do we have? What's missing? |
| ❤️ Red | Emotions | How do users feel about this? Gut reaction? |
| ⚫ Black | Caution | What could go wrong? Risks? |
| 💛 Yellow | Benefits | What's the upside? Best case scenario? |
| 💚 Green | Creativity | What alternatives exist? Wild ideas? |
| 🔵 Blue | Process | What's the next step? How do we decide? |

### First Principles Thinking
Break down to fundamentals:

1. **What problem does this solve?** (core purpose)
2. **What are the essential components?** (can't remove these)
3. **What assumptions are we making?** (challenge each one)
4. **What would we build from scratch?** (ignore existing solution)

### Jobs To Be Done (JTBD)
Focus on user motivation:

```
When [situation], I want to [motivation], so I can [outcome].
```

Examples:
- "When an employee can't come to work, they want to notify quickly, so they can avoid policy violations"
- "When a manager sees absences, they want to spot patterns, so they can address root causes"

## Industry Analysis Framework

When exploring new industries, analyze:

### Market Factors
| Factor | Questions |
|--------|-----------|
| **Pain Severity** | How much does this problem hurt? Daily? Costly? |
| **Frequency** | How often does this happen? Daily, weekly, monthly? |
| **Current Solutions** | What do they use now? Spreadsheets? Nothing? |
| **Willingness to Pay** | Would they pay for this? How much? |
| **Decision Maker** | Who buys? User vs. manager vs. executive? |

### Technical Fit
| Factor | Questions |
|--------|-----------|
| **SMS Relevance** | Do workers have smartphones? Prefer SMS? |
| **AI Value** | Is informal text parsing valuable here? |
| **Multi-tenant Need** | Multiple organizations? B2B model? |
| **Compliance** | Regulatory requirements? HIPAA, OSHA, etc.? |

### Competitive Landscape
- **Direct competitors**: Same solution, same market
- **Indirect competitors**: Different solution, same problem
- **Substitutes**: Workarounds people use today

### Feasibility Quick Check
- ✅ Can build MVP in < 2 weeks?
- ✅ Reuses > 50% of existing code?
- ✅ Clear first customer in mind?
- ✅ Solves problem 10x better than alternatives?

## MVP Thinking

### Minimum Viable Product Checklist
1. **Core value only** - What's the ONE thing it must do?
2. **Manual where possible** - Automate later
3. **Ugly is fine** - Function over form
4. **One user type** - Expand later
5. **One use case** - Nail it before expanding

### Build-Measure-Learn Loop
```
┌─────────────────────────────────────┐
│  1. BUILD: Smallest testable thing  │
│              ↓                      │
│  2. MEASURE: Did it work?           │
│              ↓                      │
│  3. LEARN: What did we discover?    │
│              ↓                      │
│  (repeat)                           │
└─────────────────────────────────────┘
```

## Questions to Drive Better Brainstorming

### Opening Questions
- "What's the real problem we're solving?"
- "Who feels this pain most acutely?"
- "What would a 10x better solution look like?"

### Expansion Questions
- "What adjacent problems could we solve?"
- "What if we had unlimited resources?"
- "What would [company X] do with this technology?"

### Challenge Questions
- "Why hasn't someone built this already?"
- "What's the hardest part of this idea?"
- "What would make users NOT want this?"

### Focus Questions
- "If we could only solve one thing, what is it?"
- "What's the fastest path to first paying customer?"
- "What can we learn in the next week?"

## Brainstorming Session Structure

### Phase 1: Diverge (15 min)
- Generate as many ideas as possible
- No judgment, no filtering
- Build on others' ideas ("Yes, and...")
- Quantity over quality

### Phase 2: Cluster (5 min)
- Group similar ideas
- Name each cluster
- Identify themes

### Phase 3: Evaluate (10 min)
- Apply evaluation matrix
- Discuss top 3-5 ideas
- Identify quick wins vs. big bets

### Phase 4: Decide (5 min)
- Pick 1-2 to explore further
- Define next action
- Set timeline for follow-up
